## What is Interaction Design?

### Broad Definition

**Interaction Design**:

> The design of interactions between people and products (apps, websites, mobile phones, game consoles, watches, wearables, etc.)

**Goal**: Create products that enable users to achieve their objectives in the best way possible

**Alternative Definition**:

> "Designing interactive products containing embedded electronics that respond to people's actions"
> 
> - Rogers, Sharp & Preece, Interaction Design (2011)

### The Interaction Design Triangle

```
PEOPLE ←→ DESIGN ←→ TECHNOLOGY
(NEEDS)              (POSSIBILITIES)
```

**Core Focus**:

- Designing useful and usable technologies
- Designing interactions with technologies
- Choreographing how people interact with digital technology

### What Interaction Designers Do

**Primary Role**: Choreograph how people interact with digital technology

**Good Interaction Design**:

- Supports people through appropriate technologies
- Requires knowledge of:
    - What technologies & people can do (or can't) - FUTURE
    - What is happening (or not) - NOW
    - What has happened (or not) - PAST

### Five Dimensions of Interaction Design

**1D - Words**

- Text and typography
- Clear, simple language
- Labeling and instructions

**2D - Visual Representations**

- Images, graphics, icons
- Typography, diagrams
- Visual hierarchy and composition

**3D - Physical Objects or Spaces**

- Hardware form factors
- Physical input devices
- Spatial design

**4D - Time**

- Animation, motion
- Sound, video
- Change over time
- Temporal feedback

**5D - Behaviour**

- How users interact with the system
- Actions and reactions
- Emotions and responses
- User behavior patterns

### Relationship to Other Fields

**Interdisciplinary Fields**:

- Human-Computer Interaction (HCI)
- Human Factors
- Cognitive Engineering
- Cognitive Ergonomics
- Information Systems

**Design Practices**:

- Graphic design
- Product design
- Artist design
- Industrial design
- Film industry

**Academic Disciplines**:

- Psychology
- Social sciences
- Computing sciences
- Engineering
- Ergonomics

**Key Insight**: Interaction Design sits at the intersection of all these disciplines, drawing from each to create better user experiences

## Affordances

### Definition

**Affordance**:

> An affordance provides a visual clue to the function and use of an object (Norman, 1988)

**Norman's Original Definition**:

> "...the term affordance refers to the perceived and actual properties of the thing, primarily those fundamental properties that determine just how the thing could possibly be used"

### Key Concept

**Affordances = Action Possibilities**

```
Capabilities of     matching    Properties of
   a person      ←─────────→    an object
```

**Possible Actions**: Push, pull, slide, turn, press, lift... **Design Goal**: It should be obvious how a control is used

### Physical Affordances

**Real Affordances**:

- Physical objects usually have obvious clues about usage
- Examples: seats, door handles
- Tactile feedback and material properties provide information
- Form meets function

**Examples of Good Physical Affordances**:

- **Handles**: Form suggests pulling
    - Horizontal bar = pull
    - Vertical plate = push
- **Knobs**: Shape suggests turning
- **Buttons**: Surface suggests pressing
- **Slots**: Opening suggests inserting
- **Balls**: Shape suggests throwing or bouncing

**Gibson's Principle (1979)**:

> "...if a surface is horizontal, flat, extended, rigid, and knee-high relative to a perceiver, it can in fact be sat upon"

> With these properties, the surface "should look sit-on-able"

**Design Application**: Take this idea and turn it into design!

### Virtual Affordances

**Perceived Affordances**:

- Graphical user interface objects lack tactile feedback
- Must rely on learned conventions
- Use design standards for graphical elements:
    - Buttons
    - Icons
    - Links
    - Scrollbars
    - Checkboxes

**Challenge**: How do we indicate that a virtual button affords dragging, selecting, highlighting?

**Design Solutions**:

- Visual styling (shadows, borders, gradients)
- Color changes on hover
- Cursor changes
- Animation hints
- Consistent patterns

### Examples of Affordances in Practice

**Physical Objects**:

- **Turkish tea set**: Handle position and shape indicate how to pour
- **Gardening tools**: Shape of handles indicates grip and action
- **Surfboard**: Shape and size indicate standing and balance

**Virtual Objects**:

- **Media player controls**: Icons suggest play, pause, stop, skip
- **Scroll bars**: Arrows and draggable elements suggest movement
- **Phone interfaces**: Green button suggests answer, red suggests decline
- **Login forms**: Text fields suggest typing, buttons suggest clicking
- **Folder icons**: Visual representation suggests containment and opening
- **Trash/recycle bin**: Visual metaphor suggests deletion

### Poor Affordances

**Problems Occur When**:

> When apparent affordances of an artifact match its intended use, the artifact is easy to operate

> When apparent affordances suggest different actions than those for which the object is designed, errors are common, and signs are necessary

**Examples of Poor Affordances**:

- **Double doors with unclear push/pull**: Users try the wrong action
- **Handles on both sides of door**: Unclear whether to push or pull
- **Flat touchscreens**: No tactile feedback for button location

**Consequences**:

- User confusion
- Increased error rates
- Need for additional signifiers
- Frustration

### Anti-Affordances

**Purpose**: To give a clue of what NOT to do

**Examples**:

- **Spikes on ledges**: Prevent sitting or climbing
- **Patterned screens on windows**: Prevent birds from flying into glass
- **Curved bench tops**: Prevent skateboarding
- **Rough surfaces under bridges**: Discourage sleeping

**Design Principle**: Sometimes preventing actions is as important as enabling them

### Why Affordances Are Important

**Benefits**:

1. Users can figure out what to do when encountering a system for the first time
2. Physical/virtual properties suggest functionality
3. Clear indication of what to do and what not to do
4. Enable intuitive understanding of system use
5. Reduce cognitive load
6. Minimize errors
7. Improve user satisfaction

**Design Goal**: Enable people to intuitively understand how to use a system

> [!tip] Design Takeaway Good affordances make the user experience self-evident. When designing, always ask: "Does the form clearly communicate the function?"

## Signifiers

### Definition

**Signifier**:

> A sign, label, hint, or short instruction that communicates the purpose, structure, and operation of a device

**Examples of Signifier Text**:

- "Touch to start"
- "Push to open"
- "Turn to release"
- "Press and hold"
- "Turn clockwise to open"
- "Pull +"

### When to Use Signifiers

**Signifiers are needed when**:

- Affordances fail
- Affordances aren't obvious
- Affordances aren't fully well-designed

**Purpose**:

- Better communicate purpose, structure, and operation
- Help users understand how to use correctly
- Reduce errors in usage
- Provide explicit guidance

### Key Characteristics

**Signifiers are descriptors of ACTION, not the object**:

```
✓ CORRECT: "Push", "Pull", "Slide", "Turn"
✗ INCORRECT: "This is a button", "Door to corridor", "Volume knob"
```

**Implementation**:

- Reduce error in usage
- Applied when users are unsure of interaction method
- Guide accurate and appropriate interaction

### Examples of Signifiers

**Physical Signifiers**:

- **Door plates**: "PUSH" or "PULL" text
- **Knobs**: Dots or lines indicating direction
- **Lock**: "Pull +" with arrow showing direction
- **Emergency exit**: "Turn clockwise to open" with icon

**Virtual Signifiers**:

- **Power button**: "Press and hold to toggle power"
- **Toggle switch**: "On" label with visual state
- **Card reader**: "Tap side" with arrow pointing to NFC area
- **Payment terminal**: "Tap to pay" instruction

### Signifiers vs. Descriptors

**Example: Payment Terminal**

**Image A** (Has Signifier):

- Shows "TAP SIDE" with arrow
- Indicates specific action and location
- Guides user to correct interaction point

**Image B** (No Signifier):

- Shows "Penny Lane" (location/name)
- Does NOT indicate action
- User must guess where and how to tap

> [!important] Critical Distinction A signifier tells you WHAT TO DO, not just what something is

### Relationship: Affordances and Signifiers

**The Love and Hate Relationship**:

**Affordances**:

- What actions are possible
- Action possibilities
- Good design communicates purpose, structure, and operation clearly

**Signifiers**:

- Clear directions for use when possible actions aren't fully clear
- Signals for interaction
- Critical when affordances are poorly designed

**Design Hierarchy**:

1. **Prioritize good affordances** over lazy design signifiers
2. Provide signifiers so users understand how to use product/service
3. Provide signs of:
    - What it is for
    - What is happening
    - What alternative actions are available

**Ideal Scenario**: Good affordances make signifiers unnecessary **Reality**: Signifiers often needed to compensate for poor affordances or complex interactions

### Why Signifiers Are Important

**Benefits**:

1. Users receive guidance on what to do and how to do it
2. Explicit instruction reduces ambiguity
3. Works as attachment to actual object or interface
4. Enables people to perform actions in an instructed way
5. Reduces trial-and-error learning
6. Particularly helpful for first-time users

**Design Goal**: Enable people to perform actions correctly without extensive exploration

> [!tip] Design Takeaway Use signifiers strategically. They should clarify, not clutter. If you need many signifiers, your affordances probably need improvement.

## Constraints

### Definition

**Constraint**:

> Restricting the possible actions that can be performed, usually limiting choices

### Why Use Constraints?

**Benefits**:

1. Help prevent users from selecting incorrect options
2. Prevent users from making mistakes
3. Let people determine proper course of action without hesitation
4. Guide decision-making, even in new situations
5. Reduce cognitive load
6. Simplify interaction

### Examples of Constraints

**Physical Constraints**:

- **Batteries**: Must be inserted in specific orientation
- **USB cable**: Can only be inserted one way (or two ways for USB-C)
- **Dishwasher**: Plates only fit in designated slots
- **Jigsaw puzzle pieces**: Only fit in correct position

**Digital Constraints**:

- **Mouse cursor**: Does not move past screen edge
- **Disabled menu items**: Greyed out when unavailable
- **Date picker**: Cannot select dates in the past
- **Form validation**: Must enter email format correctly
- **Quiz interface**: Cannot see next question until current one answered

**Behavioral Constraints**:

- **Red traffic light**: Must not continue
- **Locked door**: Cannot enter without key/permission
- **Age verification**: Must confirm age before proceeding

### Implementation Methods

**Visual Techniques**:

1. **Greying out**: Unavailable options appear faded
2. **Disabling selection**: Element cannot be clicked/selected
3. **Hiding options**: Irrelevant choices not shown
4. **Progressive disclosure**: Show options only when relevant

**Example: Hotel Booking System**

```
Constraints visible in interface:
- Check-out date must be after check-in date
- Past dates greyed out in calendar
- Number of adults must be ≥ 1
- Number of rooms must be ≥ 1
- Options limited based on previous selections
```

**Example: Text Editor**

```
Photoshop Edit Menu:
- "Undo" greyed out when nothing to undo
- "Paste" greyed out when clipboard empty
- "Fill..." option available only with selection active
```

**Example: Calendar Date Picker**

```
April 2018 dates (in past):
- All dates greyed out and unselectable
- Only future dates (May 2018) are clickable
- Current selection date highlighted
```

### Why Constraints Are Important

**Benefits**:

1. Improve people's capacity to think in less complicated ways
2. Users make fewer errors in system use
3. Reduce decision fatigue
4. Guide users to correct actions
5. Prevent invalid states
6. Create more predictable interactions

**Decision-Making Flow**:

```
Complex choices
    ↓
Constraints applied
    ↓
Simplified options
    ↓
Easier decision
    ↓
Correct action
```

**Design Goal**: Make the right action easy and the wrong action difficult or impossible

> [!tip] Design Takeaway Strategic use of constraints reduces user errors and cognitive load. Don't show users options they shouldn't or can't take.
