## Definition and Core Concepts

### Message Authentication

**Definition**: A process of verifying that the received message comes from the alleged source and has not been altered.

**Key Properties Verified**:

- **Authenticity**: Message comes from claimed sender
- **Integrity**: Message has not been modified in transit

### Methods and Tools for Authentication

- **Digital Signatures**
- **Message Authentication Code (MAC)**
- **Encryption**
- **Hash Functions**

## Authentication Functions Architecture

### Two-Level Functionality

1. **Lower Level**: Produces a value (authenticator) to authenticate a message
2. **Higher Level**: Authentication protocol that uses the lower-level function as a primitive to enable receiver verification

### Types of Authenticators

- **Hash Function**: Serves as an authenticator
- **Message Encryption**: The ciphertext of the entire message serves as its authenticator
- **Message Authentication Code (MAC)**: A function of the message and secret key that produces a fixed-length value serving as authenticator

## Authentication Types

### One-Way Authentication

- One party is authenticated by the other party
- Unidirectional verification

### Two-Way Authentication

- Party A is authenticated by Party B, and vice versa
- Mutual authentication

### Common Attacks

- **Disclosure**: Unauthorized access to information
- **Masquerade**: Impersonation of legitimate user
- **Repudiation**: Denial of message sending/receiving
- **Modification**: Alteration of content, sequence, or timing

## Symmetric-Key Message Encryption

### Basic Concept

- **Shared Key (K)**: Used by both parties A and B
- **Authentication Assurance**: B is assured that message M was generated by A and has not been altered, because only A has key K (opponent does not have K)

### Challenges with Arbitrary Bit Patterns

**Problem**: When message is an arbitrary bit pattern (meaningless sequence of bits)

- Cannot be verified after decryption

**Solutions**:

1. Make plaintext have recognizable structure
2. Add a checksum before encryption

### Internal Error Control Method

**Process**:

```
1. Input M to function F → produces FCS (Frame Check Sequence)
2. Append FCS to M → forms new block
3. Encrypt new block → transmit to B
4. B decrypts incoming block
5. B applies F to reproduce FCS
6. If calculated FCS = incoming FCS → message is authentic
```

**Security**: Unlikely that random sequence of bits would exhibit desired result

### External Error Control Method

**Process**:

```
1. Encrypt M
2. Input encrypted M to function F → produces FCS
3. Transmit encrypted M + FCS to B
4. B decrypts incoming block
5. B applies F to reproduce encrypted M
6. B decrypts M
```

**Vulnerability**: Opponent can construct message with valid error control code, creating confusion and disrupting operation

## Asymmetric-Key Message Encryption

### Public Key Encryption Limitations

- **Provides**: Confidentiality
- **Does NOT Provide**: Authentication
- **Reason**: Opponent could also use B's public key to encrypt a message, claiming to be A

**Communication**: `A → B: E_KUb[M]`

### Message Signing

- **Provides**: Authentication (B knows M came from A)
- **Does NOT Provide**: Confidentiality (opponent can use A's public key to decrypt)
- **Requirement**: Need to distinguish well-formed plaintext from random bits

**Communication**: `A → B: E_KRa[M]`

### Message Encryption and Signing Combined

- **Method**: Sign then encrypt the message
- **Provides**: Both authentication and confidentiality
- **Cost**: Public key algorithm must be executed four times per communication

**Communication**: `A → B: E_KUb[E_KRa[M]]`

## Message Authentication Code (MAC)

### Definition and Purpose

**MAC (Cryptographic Checksum)**:

- Uses a secret key to generate a small fixed-size block of data
- Known as checksum or MAC
- A and B share a secret key

**Basic Communication**: `A → B: M, C_K(M)`

### MAC with Confidentiality

#### Method 1: Encrypt After MAC

- Encrypt the message after computing MAC
- Ties MAC to the message

**Communication**: `A → B: E_K2[M, C_K1(M)]`

#### Method 2: Encrypt Before MAC

- Encrypt the message before computing MAC
- Ties MAC to the encrypted message

**Communication**: `A → B: E_K2[M], C_K1(E_K2[M])`

## Message Authentication by Hash

### Basic Hash Authentication

**Properties**:

- Accepts variable size message
- Outputs fixed size hash code (hash value)
- A and B share a key

#### Method 1: Encrypt Message and Hash

- Hash M and tie it to M
- Encrypt M||H(M)

**Communication**: `A → B: E_k[M, H(M)]`

#### Method 2: Encrypt Hash Only

- Only hash code is encrypted
- Hash code is tied to the message
- **No confidentiality provided**

**Communication**: `A → B: M, E_K[H(M)]`

### Public Key Hash Authentication

#### Signed Hash Method

- A has secret-public key pair (K_Ra, K_Ua)
- B has A's public key
- Hash code is signed
- **No confidentiality provided**

**Communication**: `A → B: M, E_KRa[H(M)]`

#### Combined Authentication and Confidentiality

- A and B share a key
- A has a private-public key pair
- Sign the hash code and tie it to message
- Message is encrypted using symmetric key

**Communication**: `A → B: E_K[M||E_KRa[H(M)]]`

### Shared Secret Hash Methods

#### Authentication Only

- A and B share a common secret value S
- **No confidentiality**

**Communication**: `A → B: M, H(M||S)`

#### Authentication with Confidentiality

- A and B share a secret key
- Provides both authentication and confidentiality

**Communication**: `A → B: E_K[M||H(M||S)]`

## MAC based on DES

### Data Authentication Code (DAC) using DES CBC

**Setup**:

- Data to be authenticated is divided into 64-bit blocks: D₁, D₂, ..., Dₙ
- Uses DES Cipher Block Chaining (CBC) mode

**Algorithm**:

```
O₁ = E_K(D₁)
O₂ = E_K(D₂ ⊕ O₁)  
O₃ = E_K(D₃ ⊕ O₂)
...
Oₙ = E_K(Dₙ ⊕ Oₙ₋₁)

DAC = Oₙ (final output block)
```

**Where**:

- `E_K` = DES encryption with key K
- `⊕` = XOR operation
- `DAC` = Data Authentication Code (final authenticator)

### Key Characteristics

- **Block Size**: 64 bits (standard DES block size)
- **Output**: Fixed-length authenticator (DAC)
- **Security**: Based on DES encryption strength
- **Chaining**: Each block depends on previous blocks, providing integrity for entire message

## Key Takeaways

### Security Considerations

1. **Symmetric Key Systems**: Require secure key distribution but provide both confidentiality and authentication
2. **Asymmetric Key Systems**: Solve key distribution but require careful design to provide both properties
3. **Hash Functions**: Efficient for authentication but require additional mechanisms for key management
4. **MAC Systems**: Purpose-built for authentication, offering good balance of security and efficiency

### Practical Applications

- **Network Protocols**: TLS/SSL use MAC for message integrity
- **Digital Communications**: Email security, secure messaging
- **Data Storage**: File integrity verification
- **Financial Systems**: Transaction authentication

### Design Principles

- **Defense in Depth**: Combine multiple authentication methods
- **Key Management**: Critical for all symmetric approaches
- **Performance vs Security**: Balance computational cost with security requirements
- **Attack Resistance**: Consider various attack vectors (masquerade, modification, replay)
